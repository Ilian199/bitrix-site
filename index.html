Что делаю

По сумме сделки, загрузке менеджера или истории клиента — не поровну «на глаз», а по правилам вашего отдела продаж.

02

Интеграция сайта с CRM

Заявка с формы на сайте сразу становится сделкой в Bitrix24 — через REST API и вебхуки, без ручного переноса.

03

Бизнес-процессы с согласованием

Для сделок, которые должен подтвердить руководитель, прежде чем менеджер возьмёт их в работу.

04

Задачи и уведомления

Чтобы заявка не «повисла» после назначения — менеджер сразу получает задачу с дедлайном.

Сайт с формой, напрямую подключённый к CRM

Заявка с сайта проходит проверку на дубль клиента, распределяется между менеджерами по сумме сделки, а крупные сделки уходят на согласование — прежде чем считаться взятыми в работу.

Почему это не «пять минут в настройках»

Распределение по очереди Bitrix24 умеет сам, без специалиста. Здесь другое: реальная интеграция внешнего сайта с CRM через REST API, точная проверка клиента на дубль по номеру телефона — официальным методом, а не по формальному ID, — и кастомная логика согласования в конструкторе бизнес-процессов.

Разобранный кейс · Телефония

Пропущенный звонок не остаётся без ответа

Если клиенту позвонили и не дозвонились, сделка не зависает в общем потоке: она отдельно помечается, а менеджер получает задачу перезвонить — с дедлайном, а не «когда вспомнит».

Где здесь настоящая работа, а не готовая функция

В Bitrix24 нет готового блока «если не дозвонились — напомни». Событие пропущенного звонка нужно поймать триггером, завести для него отдельную стадию воронки и правильно расположить сам триггер — в Bitrix24 он всегда переводит сделку на свою стадию, а не с неё, и это не очевидно из документации. Ловится только на практике.

01Звонок клиенту зафиксирован как пропущенный в CRM
02Сделка автоматически уходит на отдельную стадию «Недозвон»
03Менеджеру ставится задача «Перезвонить клиенту» с коротким дедлайном
04Проверено через REST API — без реальной АТС и без оплаты номера

Разобранный кейс · Мультиканальность

Заявки из разных каналов сходятся в одну воронку сами

Сайт, Telegram, WhatsApp — все обращения попадают в CRM с пометкой источника. Если клиент написал дважды в разные каналы, система сама найдёт совпадение по телефону, пометит повторное обращение и уведомит менеджера — вместо дубля карточки.

Почему это не «пять минут в настройках»

Сами каналы Bitrix24 подключает из коробки. Работа начинается дальше: свести обращения к одному клиенту — это правила поиска совпадений по номеру телефона и отдельная логика для повторного обращения, чтобы вместо второй карточки менеджер получил пометку и уведомление.

01Обращение приходит с сайта, Telegram или WhatsApp
02В CRM создаётся сделка с пометкой источника
03Система ищет совпадение по номеру телефона
04Повторное обращение помечается, менеджер получает уведомление — вместо дубля карточки
